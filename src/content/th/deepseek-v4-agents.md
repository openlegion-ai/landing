# รัน DeepSeek Agents อย่างปลอดภัยด้วย OpenLegion

**DeepSeek-based agents** ผสาน DeepSeek model กับการใช้เครื่องมือแบบอัตโนมัติ — และ OpenLegion คือ AI agent framework ที่ทำให้พวกมันปลอดภัย ข้อมูลรับรองที่เก็บใน vault, การรันในแซนด์บ็อกซ์สำหรับทุกงาน และการควบคุมงบประมาณรายเอเจนต์มาให้เป็นค่าเริ่มต้น โมเดลถูกเลือกด้วยพรีเซ็ต — Smartest, Smart หรือ Normal — และงานถูกคิดเป็นเครดิต เครดิตละ $0.001

<!-- SCHEMA: DefinitionBlock -->

> **DeepSeek-based agents คืออะไร**
> DeepSeek-based agents คือ AI agent อัตโนมัติที่ขับเคลื่อนด้วยโมเดล DeepSeek (เช่น `deepseek-chat` หรือ `deepseek-coder`) เมื่อดีพลอยผ่าน AI agent framework อย่าง OpenLegion พวกมันสามารถเรียกใช้งานหลายขั้นตอน, เรียก API, สร้างโค้ด และประมวลผล input — โดยมีการรันในแซนด์บ็อกซ์ต่องานและข้อมูลรับรองที่เก็บใน vault บังคับใช้ที่ระดับแพลตฟอร์ม

## TL;DR

- **โมเดลผ่านพรีเซ็ต** OpenLegion รันเอเจนต์ทุกตัวบนพรีเซ็ตโมเดล — Smartest, Smart หรือ Normal — เลือกต่อเอเจนต์หรือต่อ workspace โดยไม่มีบัญชีผู้ให้บริการหรือ endpoint ให้ตั้งค่า
- **ข้อมูลรับรองที่เก็บใน vault** ข้อมูลรับรองไม่เคยเข้าไปใน context ของโมเดล มันอยู่ใน vault และถูกฉีดเข้าไปนอกโมเดล ซึ่งถือเพียง handle เท่านั้น
- **การรันในแซนด์บ็อกซ์** แต่ละงานรันตามต้องการแล้วหยุด และโค้ดใดที่เอเจนต์เขียนรันในแซนด์บ็อกซ์ที่ไม่มีการเข้าถึงเครือข่ายเป็นค่าเริ่มต้น
- **การควบคุมงบประมาณรายเอเจนต์** เอเจนต์ทุกตัวมีงบประมาณเครดิตของตัวเองพร้อมการตัดเข้มงวดอัตโนมัติ — จำเป็นสำหรับเวิร์กโหลด agent ที่จำนวนการวนซ้ำคาดเดาไม่ได้
- **ความปลอดภัยที่ไม่ขึ้นกับโมเดล** ไม่ว่าโมเดลใดอยู่หลังพรีเซ็ต OpenLegion ให้การรับประกัน [ความปลอดภัย AI agent](/learn/ai-agent-security)เดียวกัน: ข้อมูลรับรองที่เก็บใน vault, การรันในแซนด์บ็อกซ์ และใบเสร็จของทุกการกระทำ
- **ไม่ผูกกับโมเดลใด** เอเจนต์เดียวกัน เครื่องมือเดียวกัน ความปลอดภัยเดียวกัน — ย้ายเอเจนต์ระหว่างพรีเซ็ตในแอป โมเดลที่ถูกกว่าอาจเป็นตัวเลือกที่ถูกต้องสำหรับทีมเอเจนต์ที่ใส่ใจต้นทุน

## ทำไม DeepSeek-Based Agents จึงต้องการ Framework ที่ปลอดภัย

### โมเดลทรงพลัง รัศมีความเสียหายกว้าง

DeepSeek-powered agent ที่เข้าถึงเครื่องมือสามารถ:
- อ่านและแก้ไขไฟล์ใน workspace ของตัวเอง
- สร้างและรันโค้ด
- เข้าถึง API, ฐานข้อมูล และบริการภายนอก (ขึ้นอยู่กับสิทธิ์)
- ให้เหตุผลบน context ขนาดใหญ่

หากไม่มี [AI agent runtime](/learn/ai-agent-platform) ที่เหมาะสม เอเจนต์อัตโนมัติก็สามารถ:
- พยายามเข้าถึง API key และข้อมูลรับรองของคุณ
- สะสมค่า API ที่ไร้ขอบเขตบน endpoint ที่คิดค่าใช้จ่ายตามการใช้งาน
- ส่งผลกระทบต่อเอเจนต์อื่นหรือโฮสต์หากรันไทม์ไม่มีการแยก
- เรียกใช้งานเส้นทาง workflow ที่ไม่ได้ตรวจสอบ
- ตกเป็นเหยื่อของ vector prompt injection ใน context ที่ผู้ใช้ป้อน

OpenLegion — แพลตฟอร์ม AI agent ที่โฮสต์ให้ — แก้ปัญหานี้ด้วยการรับประกันทางสถาปัตยกรรมสามประการ:

**ข้อมูลรับรองที่เก็บใน vault** ข้อมูลรับรองของคุณไม่เคยเข้าไปใน context ของโมเดล มันอยู่ใน vault และถูกฉีดเข้าไปนอกโมเดล ซึ่งถือเพียง handle เท่านั้น แม้โมเดลจะถูกชี้นำให้ค้นหาข้อมูลรับรอง ก็ไม่มีอะไรให้ค้นเจอในการรัน

**การรันงานในแซนด์บ็อกซ์** แต่ละงานรันตามต้องการแล้วหยุด และโค้ดใดที่เอเจนต์เขียนรันในแซนด์บ็อกซ์ที่ไม่มีการเข้าถึงเครือข่ายเป็นค่าเริ่มต้น เอเจนต์ที่ถูกบุกรุกไม่สามารถส่งผลกระทบต่อเอเจนต์อื่น แพลตฟอร์ม หรือคลังข้อมูลรับรองของคุณ

**การบังคับงบประมาณรายเอเจนต์** เอเจนต์ทุกตัวมีงบประมาณเครดิตของตัวเอง บังคับใช้พร้อมการตัดเข้มงวดอัตโนมัติ ไม่มีเอเจนต์ใดเผาเครดิตของคุณข้ามคืน

## หมายเหตุการตั้งค่าโมเดล DeepSeek

DeepSeek เผยแพร่โมเดลเช่น `deepseek-chat` และ `deepseek-coder` รวมถึง release ที่เน้นการให้เหตุผลเป็นระยะ รายการที่แน่นอนและราคาเปลี่ยนแปลงตามเวลา ปรึกษา[เอกสารของ DeepSeek](https://api-docs.deepseek.com/)สำหรับรายการล่าสุด ข้อพิจารณาเชิงปฏิบัติสำคัญสำหรับเวิร์กโหลด agent:

- **การ route** OpenLegion route ด้วยพรีเซ็ต คุณเลือก Smartest, Smart หรือ Normal ให้เอเจนต์ แล้วแพลตฟอร์มรันโมเดลที่อยู่ข้างหลัง; ไม่มี model ID หรือบัญชี aggregator ให้จัดการ
- **Context window และราคา** แตกต่างกันตามโมเดล ตรวจสอบเอกสาร DeepSeek สำหรับต้นทุนต่อ token ปัจจุบัน งบประมาณรายเอเจนต์ของ OpenLegion เป็นตัวสำรองด้านความปลอดภัยไม่ว่าจะเป็นโมเดลใด
- **Open weights** โมเดล DeepSeek บางสายปล่อย open weights ทีมจึงรันบน GPU ของตัวเองด้วย Ollama หรือ vLLM ได้ OpenLegion เป็นแบบโฮสต์ให้และรันโมเดลที่อยู่หลังพรีเซ็ตที่คุณเลือก — การรับประกันด้านความปลอดภัยของมันใช้กับทุกงานไม่ว่าทางใด

## วิธีรัน DeepSeek-Based Agents บน OpenLegion

การตั้งค่าเอเจนต์ใช้เวลาประมาณ 30 วินาทีในแอปที่โฮสต์ให้ — ไม่มีไฟล์ config ไม่ต้องแก้ YAML ไม่มีอะไรต้องติดตั้ง เข้าสู่ระบบด้วย Google แล้วเอเจนต์ตัวแรกก็พร้อม

### ขั้นตอนที่ 1: เลือกผู้ให้บริการ LLM

ไม่มีผู้ให้บริการให้เลือก: OpenLegion รันโมเดลให้คุณ คุณเลือกพรีเซ็ตแทน — Smartest, Smart หรือ Normal — ต่อเอเจนต์หรือต่อ workspace นี่คือระบบโมเดลเดียวกันที่ขับเคลื่อน[การประสานงานเอเจนต์](/learn/ai-agent-orchestration)ทั้งหมดบน OpenLegion

### ขั้นตอนที่ 2: ให้ API key ของคุณ

ไม่มี API key ของโมเดลให้วาง และไม่ต้องใช้บัตรเพื่อเริ่ม ข้อมูลรับรองที่คุณเพิ่มสำหรับเครื่องมือที่เอเจนต์ใช้ ถูกเก็บใน vault และฉีดเข้าไปนอกโมเดล เอเจนต์จึงถือเพียง handle และไม่เห็นคีย์ดิบ

### ขั้นตอนที่ 3: เลือกโมเดล

เลือกพรีเซ็ตที่คุณต้องการ — Smartest, Smart หรือ Normal — สำหรับเอเจนต์นั้นหรือทั้ง workspace เสร็จเรียบร้อย เอเจนต์ของคุณกำลังรันด้วยข้อมูลรับรองที่เก็บใน vault, การรันในแซนด์บ็อกซ์ต่องาน และการบังคับงบประมาณ — สแต็กความปลอดภัยเดียวกันที่ใช้กับทุกโมเดลที่ OpenLegion รัน

แค่นั้นเอง แอปจัดการโมเดล vault จัดการข้อมูลรับรองของคุณ และแพลตฟอร์มจัดการแซนด์บ็อกซ์และงบประมาณ

### รัน DeepSeek ในเครื่องด้วย open weights

ทีมสามารถรัน DeepSeek open weights บน GPU ของตัวเองผ่าน Ollama, vLLM หรือ inference server อื่น ซึ่งทำให้ inference อยู่ในองค์กร OpenLegion เองเป็นแบบโฮสต์ให้: ไม่มีตัวเลือก self-host และไม่มี endpoint ในเครื่องให้ชี้ไป และโมเดลที่อยู่หลังแต่ละพรีเซ็ตรันบนแพลตฟอร์ม สิ่งที่ OpenLegion ให้คือทุกอย่างรอบโมเดล — การรันในแซนด์บ็อกซ์, การควบคุมการเข้าถึงเครื่องมือ, การมอบหมาย และงบประมาณรายเอเจนต์

### การสลับโมเดล — DeepSeek เป็นทางเลือกแทน Claude หรือ GPT

ต้องการเปรียบเทียบโมเดลที่ถูกกว่ากับโมเดล frontier ในงานเดียวกันใช่ไหม เปลี่ยนพรีเซ็ตของเอเจนต์ในแอป เอเจนต์เดียวกัน เครื่องมือเดียวกัน ความปลอดภัยเดียวกัน — โมเดลต่างกัน ดู[การเปรียบเทียบ AI agent framework](/learn/ai-agent-frameworks)สำหรับการแยกย่อยข้ามผู้ให้บริการ

## เวิร์กโฟลว DeepSeek-Based Agent

### Context ยาวเปิดทาง agent ระดับ repo

โมเดลในตระกูล DeepSeek สมัยใหม่รองรับ context window ขนาดใหญ่ เปิดทางเวิร์กโฟลว agent เช่น:

- **การ review โค้ดทั้ง repository** ในครั้งเดียว (เมื่อ context window อนุญาต)
- **การ refactor ข้ามไฟล์** พร้อมการรับรู้ dependency ที่กว้างขึ้น
- **การสร้างเอกสาร** จาก context โครงการขนาดใหญ่
- **การตรวจสอบความปลอดภัย** ข้าม codebase

OpenLegion ทำให้การดำเนินการ context ยาวเหล่านี้มีขอบเขต: แต่ละงานรันตามต้องการแล้วหยุด และทุกการปลุกถูก policy engine ตรวจสอบและคิดค่าใช้จ่าย — งบประมาณรายเอเจนต์ป้องกัน prompt ขนาดใหญ่เกินไปจากการกินโควต้ารายเดือนของคุณทั้งหมด

### ความสามารถในการคาดการณ์ต้นทุนด้วยการตัดที่เข้มงวด

โมเดล DeepSeek มีราคาต่ำกว่าทางเลือก frontier ฝั่งตะวันตกในอดีต ซึ่งทำให้น่าสนใจสำหรับเวิร์กโหลด agent ที่มีการวนซ้ำสูง แต่ "ถูกกว่าต่อการเรียก" ก็ยังกลายเป็น "แพงเมื่อรวม" ได้เมื่อเอเจนต์วนซ้ำอย่างเสรี งบประมาณเครดิตรายเอเจนต์และการตัดเข้มงวดของ OpenLegion ป้องกันต้นทุนพุ่งจากการขยายผลข้ามทีม

## ข้อพิจารณาด้านความปลอดภัยสำหรับ DeepSeek-Based Agents

### Open weights เป็นทั้งฟีเจอร์และพื้นที่เสี่ยง

การปล่อย open-weight ของ DeepSeek เป็นชัยชนะที่แข็งแกร่งสำหรับการดีพลอย self-host และความโปร่งใสของระบบนิเวศ มันยังหมายถึง:

- **variant ที่ fine-tune จะแพร่หลาย** ไม่ใช่ทุกตัวจะ align หรือผ่านการทดสอบความปลอดภัย การรันในแซนด์บ็อกซ์และข้อจำกัดเครื่องมือของ OpenLegion ใช้ได้ไม่ว่าโมเดลใดอยู่หลังพรีเซ็ต
- **งานวิจัยฝ่ายตรงข้ามทำได้ง่ายขึ้นบน open weights** เอเจนต์ที่รันโมเดล open-weight ได้ประโยชน์จาก [defense-in-depth](/learn/ai-agent-security): การรันในแซนด์บ็อกซ์, การเรียกใช้งานแบบมีขอบเขต, การให้สิทธิ์เครื่องมือที่ชัดเจน — ไม่ใช่แค่การ align ระดับโมเดล
- **สุขอนามัยของห่วงโซ่อุปทาน** การดาวน์โหลด open weights จาก Hugging Face หรือแหล่งอื่นต้องการการตรวจสอบ checksum และที่มา บันทึกไว้ว่ารัน binary โมเดลตัวใด

### Context ยาวขยายพื้นที่เสี่ยง prompt injection

Context window ขนาดใหญ่คือพื้นที่ prompt injection ที่อาจเกิดขึ้นขนาดใหญ่ เอเจนต์ที่ประมวลผลทั้ง codebase กำลังประมวลผลทุก comment, ทุก string literal, ทุก README — ใด ๆ อาจมีคำสั่งของฝ่ายตรงข้าม

การป้องกันของ OpenLegion: policy engine เดียวหน้าทุกการกระทำ, สิทธิ์เครื่องมือรายเอเจนต์, ข้อมูลรับรองที่เก็บใน vault ดังนั้น injection จึงดูดคีย์ออกไปไม่ได้ และกำแพงการอนุมัติก่อนเอเจนต์กระทำต่อเนื้อหาที่ไม่น่าเชื่อถือ สิ่งเหล่านี้จำกัดความเสียหายแม้เมื่อ injection สำเร็จ

### ข้อพิจารณาเชิงภูมิรัฐศาสตร์

สำหรับองค์กรที่อยู่ภายใต้การควบคุมการส่งออก, ข้อกำหนดด้านอธิปไตยข้อมูล หรือการปฏิบัติตามห่วงโซ่อุปทาน โหมดการดีพลอยมีความสำคัญ:

- **โหมด API:** ข้อมูลเดินทางผ่านโครงสร้างพื้นฐานที่ DeepSeek โฮสต์
- **โหมด self-host (open weights):** ข้อมูลอยู่บนโครงสร้างพื้นฐานของคุณ ขจัด dependency API ทั้งหมด
- **โหมด aggregator/ผู้ให้บริการ inference:** ข้อมูลเดินทางผ่านโครงสร้างพื้นฐานของผู้ให้บริการ (แตกต่างกันตามผู้ให้บริการ)

OpenLegion เป็นแบบโฮสต์ให้ inference จึงรันบนแพลตฟอร์ม ด้วยการรับประกัน[ความปลอดภัย AI agent](/learn/ai-agent-security)เดียวกันในทุกแพลน

## ใครควรรัน DeepSeek-Based Agents กับ OpenLegion

**ทีมที่ใส่ใจต้นทุนซึ่งรันเอเจนต์จำนวนมาก** ราคาต่อ token ที่ต่ำกว่าหมายความว่าคุณสามารถรันเอเจนต์ได้มากขึ้น บ่อยขึ้น บนงบประมาณเดียวกัน การควบคุมต้นทุนรายเอเจนต์ของ OpenLegion ทำให้ "ถูกกว่าต่อการเรียก" ไม่กลายเป็น "แพงเมื่อรวม"

**ทีมที่ต้องการให้ข้อมูลรับรองอยู่ห่างจากโมเดล** OpenLegion เก็บข้อมูลรับรองทุกตัวไว้ใน vault และฉีดเข้าไปนอกโมเดล ซึ่งถือเพียง handle เท่านั้นและไม่เคยเห็นคีย์

**ทีมที่ชั่งน้ำหนักคุณภาพโมเดลกับต้นทุน** สถาปัตยกรรมแบบไม่ผูกกับโมเดลของ OpenLegion หมายความว่าคุณสามารถรันทีมเอเจนต์เดียวกันบนพรีเซ็ตต่างกัน — เปรียบเทียบคุณภาพ, ต้นทุน และ latency ต่องาน โดยเห็นต้นทุนที่แน่นอนของแต่ละงาน ดู [OpenLegion vs OpenClaw](/comparison/openclaw) และ [OpenLegion vs LangGraph](/comparison/langgraph) สำหรับการเปรียบเทียบระดับ framework

## คำถามที่พบบ่อย

### DeepSeek-based agents คืออะไร

DeepSeek-based agents คือ AI agent อัตโนมัติที่ขับเคลื่อนด้วยโมเดล DeepSeek (เช่น `deepseek-chat` หรือ `deepseek-coder`) ที่รันภายใต้ agent framework ซึ่งให้การแยก, ข้อมูลรับรอง, เครื่องมือ, งบประมาณ และการประสานงาน OpenLegion เป็นหนึ่งใน framework เหล่านั้น — เพิ่มการรันในแซนด์บ็อกซ์ต่องาน, ข้อมูลรับรองที่เก็บใน vault และงบประมาณเครดิตรายเอเจนต์ให้กับพรีเซ็ตโมเดลใดก็ตามที่คุณเลือก

### OpenLegion รองรับ DeepSeek หรือไม่

OpenLegion รันโมเดลให้คุณ คุณจึงไม่ต้องเลือกผู้ให้บริการเลย คุณเลือกพรีเซ็ตแทน — Smartest, Smart หรือ Normal — ต่อเอเจนต์หรือต่อ workspace แล้วแพลตฟอร์มรันโมเดลที่อยู่ข้างหลัง ไม่มี API key ให้วาง ไม่มีบัญชี aggregator ให้ตั้งค่า และไม่มี inference server ให้ยกขึ้น; งานถูกคิดเป็นเครดิต เครดิตละ $0.001 โดยเห็นต้นทุนที่แน่นอนของแต่ละงาน ทำงานผ่านผู้ให้บริการ inference ที่เข้ากันได้

### ฉันจะรัน DeepSeek-based agents อย่างปลอดภัยได้อย่างไร

OpenLegion ให้สามชั้นความปลอดภัยสำหรับเอเจนต์ทุกตัว: ข้อมูลรับรองที่เก็บใน vault (ข้อมูลรับรองไม่เคยเข้าไปใน context ของโมเดล — มันอยู่ใน vault และถูกฉีดเข้าไปนอกโมเดล), การรันงานในแซนด์บ็อกซ์ (แต่ละงานรันตามต้องการแล้วหยุด และโค้ดที่เอเจนต์เขียนไม่มีการเข้าถึงเครือข่ายเป็นค่าเริ่มต้น) และการบังคับงบประมาณรายเอเจนต์ (งบประมาณเครดิตของตัวเองพร้อมการตัดเข้มงวดอัตโนมัติ) เลือกพรีเซ็ต แล้วสแต็กความปลอดภัยจะใช้โดยอัตโนมัติ

### DeepSeek ดีกว่า Claude หรือ GPT สำหรับ agent หรือไม่

ขึ้นอยู่กับงาน โมเดลในตระกูล DeepSeek โดยทั่วไปมีราคาต่ำกว่า Claude และ GPT และแข่งขันได้ในหลาย benchmark แต่ความสามารถเฉพาะแตกต่างกันตามโมเดล สำหรับเวิร์กโหลด agent การเลือกขึ้นอยู่กับข้อกำหนดของงาน, ข้อจำกัดด้านต้นทุน และความต้องการด้านที่อยู่ของข้อมูล OpenLegion รองรับทั้งสามตระกูลด้วยการรับประกันความปลอดภัยเหมือนกัน — คุณสามารถประเมินแบบเคียงข้างกันบนเวิร์กโฟลว์เดียวกัน

### ฉัน self-host DeepSeek กับ OpenLegion ได้หรือไม่

ยังไม่ได้ตอนเปิดตัว OpenLegion เป็นเว็บแอปที่โฮสต์ให้: ไม่มีตัวเลือก self-host และไม่มี endpoint ในเครื่องให้ชี้ไป ทีมที่ต้องเก็บ inference ไว้บนโครงสร้างพื้นฐาน GPU ของตัวเองสามารถรัน open weights ที่นั่นด้วย Ollama หรือ vLLM แยกจาก OpenLegion บนแพลตฟอร์มคุณเลือกพรีเซ็ต แล้วการรันในแซนด์บ็อกซ์, การควบคุมการเข้าถึงเครื่องมือ, การมอบหมาย และงบประมาณรายเอเจนต์ทั้งหมดใช้ได้

### ราคา DeepSeek เทียบกันอย่างไรสำหรับเวิร์กโหลด agent

DeepSeek โดยทั่วไปราคาต่ำกว่าโมเดล frontier ฝั่งตะวันตกบนพื้นฐานต่อ token สำหรับเวิร์กโหลด agent ที่เกี่ยวข้องกับการเรียก API ซ้ำหลายครั้ง ความต่างของต้นทุนจะทบขึ้น การควบคุมงบประมาณรายเอเจนต์ของ OpenLegion — งบประมาณเครดิตต่อเอเจนต์พร้อมการตัดที่เข้มงวด — ป้องกันถูกกว่าต่อการเรียกจากการกลายเป็นแพงเมื่อรวมเมื่อเอเจนต์วนซ้ำอย่างเสรี

### DeepSeek เป็นทางเลือกที่ดีแทน Claude สำหรับ AI agent หรือไม่

DeepSeek เป็นทางเลือกที่น่าสนใจสำหรับเวิร์กโหลด agent ที่ใส่ใจต้นทุน OpenLegion ใช้การรับประกันความปลอดภัยเหมือนกันกับทุกโมเดลที่มันรัน คุณจึงประเมินพรีเซ็ตได้แบบเคียงข้างกันบนเวิร์กโฟลว์เดียวกัน และสลับในแอปโดยไม่ต้องเปลี่ยนเอเจนต์หรือโครงสร้างพื้นฐานใด ๆ

### ปลอดภัยหรือไม่ที่จะรัน agent บนโมเดล AI จีน

คำถามเรื่องความปลอดภัยขึ้นอยู่กับโหมดการดีพลอยของคุณ DeepSeek agent แบบ self-host, open-weight หมายความว่าไม่มีข้อมูลออกจากโครงสร้างพื้นฐานของคุณ โหมด API ส่ง route ข้อมูลผ่านเซิร์ฟเวอร์ที่ DeepSeek โฮสต์ OpenLegion เป็นแบบโฮสต์ให้และรันโมเดลที่อยู่หลังพรีเซ็ตที่คุณเลือก ด้วยการรับประกันความปลอดภัยเหมือนกันในทุกแพลน สำหรับองค์กรที่มีข้อกำหนดด้านอธิปไตยข้อมูล การดีพลอย self-host ด้วย open weights ทำให้ inference อยู่บนโครงสร้างพื้นฐานของคุณ

### Context window ยาวของ DeepSeek มีประโยชน์อย่างไรสำหรับ agent

Context window ขนาดใหญ่เปิดทางเวิร์กโฟลว agent ที่ประมวลผลทั้ง codebase, ชุดเอกสารทั้งหมด หรือประวัติการสนทนายาวในครั้งเดียว — โดยไม่ต้อง chunk หรือใช้ retrieval augmentation การเรียกใช้งานแบบมีขอบเขตและงบประมาณเครดิตรายเอเจนต์ของ OpenLegion ป้องกัน prompt context ยาวที่แพงจากการเกินขีดจำกัด ไม่ว่าจะใช้โมเดลใด
