# AI Agent Platform ที่สร้างมาเพื่อโปรดักชัน

ทีมส่วนใหญ่เริ่มด้วย framework พวกเขาร้อย node LangGraph หรือ crew CrewAI เข้าด้วยกัน ทำ demo ให้ทำงานได้ แล้วก็ชนกำแพง: ใครจัดการคอนเทนเนอร์ API key ไปไหน อะไรหยุดเอเจนต์ที่แสบจากการเผา 500 ดอลลาร์ของ token ในคืนเดียว

**AI agent platform** ตอบคำถามเหล่านั้นก่อนที่คุณจะเขียนเอเจนต์แรก OpenLegion เป็นแพลตฟอร์ม AI agent แบบจัดการให้ที่มาพร้อมการรันงานในแซนด์บ็อกซ์, ข้อมูลรับรองที่เก็บใน vault, งบประมาณเครดิตรายเอเจนต์ และการประสานงานแบบเป้าหมายและงาน (เป้าหมาย → งาน → เอเจนต์) — ทั้งหมดเปิดใช้งานเป็นค่าเริ่มต้น เป็นเว็บแอปที่โฮสต์ให้: เข้าสู่ระบบด้วย Google แล้วเริ่มได้เลย ไม่มีอะไรต้องติดตั้ง

> **AI agent platform คืออะไร**
> AI agent platform คือโครงสร้างพื้นฐานแบบจัดการให้สำหรับการดีพลอย, จัดวง และกำกับดูแล AI agent อัตโนมัติในโปรดักชัน ต่างจาก framework ดิบ แพลตฟอร์มจัดการการแยก, การจัดการข้อมูลรับรอง, การควบคุมต้นทุน และการสังเกตการณ์ เพื่อให้ทีมส่งเอเจนต์ออกไปได้โดยไม่ต้องสร้าง DevOps จากศูนย์

## TL;DR

- **แพลตฟอร์ม ไม่ใช่ framework** — OpenLegion จัดการการรัน, ข้อมูลรับรอง, งบประมาณ และการอนุมัติ คุณจัดการ logic ของเอเจนต์
- **ข้อมูลรับรองที่เก็บใน vault** — ข้อมูลรับรองถูกฉีดนอกโมเดล ซึ่งถือเพียง handle เท่านั้น เอเจนต์ไม่เคยเห็นคีย์ดิบ
- **การรันในแซนด์บ็อกซ์ต่องาน** — แต่ละงานรันตามต้องการแล้วหยุด จึงไม่มีโพรเซสเอเจนต์ที่อยู่ยาวให้บุกรุก และโค้ดที่เอเจนต์เขียนรันโดยไม่มีการเข้าถึงเครือข่ายเป็นค่าเริ่มต้น
- **การบังคับงบประมาณรายเอเจนต์** — ตั้งขีดจำกัด token รายวันและรายเดือนพร้อมตัดเข้มงวดอัตโนมัติ ไม่มีบิลเซอร์ไพรส์
- **พรีเซ็ตโมเดล** — เลือก Smartest, Smart หรือ Normal ต่อเอเจนต์หรือต่อ workspace คุณไม่ต้องตั้งค่าผู้ให้บริการหรือหมุนคีย์เลย
- **การประสานงานแบบเป้าหมายและงานที่ตรวจสอบได้** — งานถูกจัดเป็นเป้าหมาย → งาน → เอเจนต์ โดยผู้ช่วยสร้างเพื่อนร่วมทีมที่ต้องการ ไม่มี "เอเจนต์ CEO" ทำการตัดสินใจที่คลุมเครือ
- **ชุดเครื่องมือในตัว** — ค้นหาและดึงข้อมูลเว็บ, ไฟล์, หน่วยความจำระยะยาว, ตารางเวลา, การรันโค้ดในแซนด์บ็อกซ์ และผลงานที่แชร์ได้ มีให้เอเจนต์ทุกตัว
- **หน่วยความจำเอเจนต์ถาวร** — เอเจนต์จดจำข้ามเซสชันด้วย vector search, ไฟล์ workspace และการเรียนรู้จากข้อผิดพลาด context จัดการอัตโนมัติ

## แบบจัดการให้ vs Self-Hosted: เมื่อใดเหมาะกับอะไร

ความแตกต่างระหว่าง AI agent framework และ AI agent platform สำคัญที่สุด ณ เวลาดีพลอย Framework ให้ building block — นิยามเอเจนต์, การผสานเครื่องมือ, รูปแบบ conversation แพลตฟอร์มให้ชั้นโปรดักชัน: เอเจนต์รันที่ไหน, เข้าถึงข้อมูลรับรองอย่างไร, อะไรหยุดพวกมันจากการหลุดราง

**Framework แบบ Self-host** (LangGraph, CrewAI, AutoGen) ให้การควบคุมสูงสุด คุณเป็นเจ้าของโครงสร้างพื้นฐาน คุณตั้งค่าคอนเทนเนอร์ คุณสร้าง pipeline ข้อมูลรับรอง สิ่งนี้ใช้ได้เมื่อทีมของคุณมีความสามารถ DevOps เฉพาะและโครงสร้างพื้นฐานที่มีอยู่ซึ่งเอเจนต์ต้องผสานเข้าลึก

**แพลตฟอร์ม AI agent แบบจัดการให้** จัดการชั้นเชิงปฏิบัติการเพื่อให้ทีมของคุณโฟกัสที่ logic ของเอเจนต์ OpenLegion อยู่ตรงนี้ — แต่มีความต่างสำคัญ: เปิดเผยซอร์สโค้ดภายใต้ PolyForm Perimeter License 1.0.1 คุณได้การดำเนินงานระดับแพลตฟอร์ม (การแยก, การ vault, การควบคุมงบประมาณ) โดยไม่มี vendor lock-in ฝั่งโครงสร้างพื้นฐาน

คำถามไม่ใช่ว่าตัวไหน "ดีกว่า" คำถามคือทีมของคุณควรใช้ชั่วโมงวิศวกรรมกับโครงสร้างพื้นฐานความปลอดภัยของเอเจนต์หรือกับเอเจนต์เอง

### เมื่อใด self-host เหมาะ

- คุณมีข้อกำหนดด้านที่อยู่ของข้อมูลที่เข้มงวดซึ่งกีดกันบริการแบบจัดการให้
- เอเจนต์ของคุณต้องผสานลึกกับโครงสร้างพื้นฐาน on-prem ที่มีอยู่
- ทีมของคุณดำเนินการคลัสเตอร์ Kubernetes อยู่แล้วและมีแนวปฏิบัติ DevOps ที่เป็นผู้ใหญ่
- คุณต้องการปรับแต่งสภาพแวดล้อมรันไทม์ในระดับที่แพลตฟอร์มจัดการให้ไม่เปิดเผย

### เมื่อใดแพลตฟอร์ม AI agent แบบจัดการให้เหมาะ

- คุณต้องการเอเจนต์ในโปรดักชันภายในวัน ไม่ใช่เดือน
- ทีมของคุณมีวิศวกร 1–5 คนและจัดสรรหัวให้โครงสร้างพื้นฐานไม่ได้
- คุณต้องการการรับประกัน[ความปลอดภัย AI agent](/learn/ai-agent-security)โดยไม่ต้องสร้างเอง
- คุณต้องการการควบคุมต้นทุนและการติดตาม request โดยไม่ต้อง instrument ทุกอย่างด้วยมือ

## ระบบพรีเซ็ตโมเดล — ทำไมจึงสำคัญ

แพลตฟอร์ม AI แบบจัดการให้ส่วนใหญ่ทำให้การเลือกโมเดลเป็นปัญหาของคุณ: เลือกผู้ให้บริการ ตั้งคีย์ หมุนคีย์ ปรับใหม่เมื่อมันเปลี่ยน สิ่งนี้สร้างสองปัญหา: ความไม่โปร่งใสของต้นทุนและ vendor lock-in

OpenLegion ใช้แนวทางต่าง โมเดลถูกเลือกด้วยพรีเซ็ต — Smartest, Smart หรือ Normal — ต่อเอเจนต์หรือต่อ workspace จึงไม่มีผู้ให้บริการให้ตั้งค่าและไม่มีคีย์ให้หมุน งานถูกคิดเป็นเครดิต เครดิตละ $0.001 และเห็นต้นทุนที่แน่นอนของทุกงานในแอป

สิ่งนี้สำคัญด้วยสามเหตุผล:

**ความโปร่งใสของต้นทุน** คุณเห็นแน่ชัดว่าเอเจนต์แต่ละตัวใช้จ่ายอะไรและแต่ละงานมีต้นทุนเท่าใด ทุกหน่วยงานคือการปลุกที่ถูกบันทึกพร้อมราคา ไม่ใช่บรรทัดในบิลรายเดือน

**ความยืดหยุ่นของโมเดล** สลับพรีเซ็ตรายเอเจนต์ รัน Smartest สำหรับการให้เหตุผลซับซ้อน, Smart สำหรับงานประจำวัน และ Normal สำหรับการ classify ปริมาณสูง — ทั้งหมดใน workspace เดียวกัน จัดการจากแดชบอร์ดเดียว

**ไม่มี lock-in** หากคุณออกจาก OpenLegion คุณ export workspace ได้ — เอเจนต์, งาน, ใบเสร็จ และผลงาน — แล้วลบสิ่งที่เหลือ ไม่มีชั้นโมเดลที่เป็นกรรมสิทธิ์ให้ต้องย้ายออก

## เหมาะกับใคร

### นักพัฒนาเดี่ยวที่สร้างผลิตภัณฑ์เอเจนต์

คุณกำลังส่งผลิตภัณฑ์ที่ขับเคลื่อนด้วยเอเจนต์และต้องการให้มันปลอดภัยตั้งแต่วันแรก OpenLegion ให้โครงสร้างพื้นฐานโปรดักชัน — การรันในแซนด์บ็อกซ์, การ vault ข้อมูลรับรอง, การควบคุมต้นทุน — โดยไม่ต้องจ้างทีม DevOps อธิบายผลลัพธ์ที่คุณต้องการ แล้วผู้ช่วยจะสร้างเพื่อนร่วมทีมที่ต้องการเพื่อไปให้ถึง

### ทีมสตาร์ทอัปที่ส่งไว

ทีมของคุณคือวิศวกร 2–10 คน คุณต้องการเอเจนต์ในโปรดักชัน sprint นี้ ไม่ใช่ไตรมาสหน้า ไม่มีอะไรต้องติดตั้ง: OpenLegion เป็นเว็บแอปที่โฮสต์ให้ และคุณเข้าสู่ระบบด้วย Google แพลนฟรีคือ $0 พร้อม 1,000 เครดิตครั้งเดียวโดยไม่ต้องใช้บัตร เอเจนต์ตัวแรกของคุณจึงทำงานได้ในไม่กี่นาทีหลังสมัคร

### ทีมความปลอดภัยองค์กร

คุณต้องการการติดตาม request และการสังเกตการณ์เวิร์กโฟลว์, การแยกข้อมูลรับรองที่ทนต่อเอเจนต์ที่ถูกบุกรุก และการควบคุมงบประมาณที่ป้องกันต้นทุนหลุดควบคุม สถาปัตยกรรมของ OpenLegion ออกแบบมาสำหรับสภาพแวดล้อมที่ต้องการ defense-in-depth การประสานงานแบบเป้าหมายและงานที่ตรวจสอบได้หมายความว่าทุกขั้นตอนเวิร์กโฟลว์ชัดเจนและติดตามได้ — ไม่มีการตัดสินใจ LLM ที่คลุมเครือใน control plane ดูหน้า[ความปลอดภัย AI agent](/learn/ai-agent-security)สำหรับ threat model เต็ม

## ความพร้อมโปรดักชัน: OpenLegion จัดการอะไรบ้างเทียบกับ DIY

| ความสามารถ | DIY (Framework เท่านั้น) | OpenLegion |
|---|---|---|
| **รันไทม์เอเจนต์** | คุณตั้งค่า Docker จัดการอิมเมจ จัดการเครือข่าย | เอเจนต์เป็นเรคคอร์ดถาวร ไม่ใช่เซิร์ฟเวอร์; แต่ละงานรันตามต้องการในแซนด์บ็อกซ์แล้วหยุด |
| **การจัดการข้อมูลรับรอง** | Environment variable หรือผสาน vault แบบกำหนดเอง | ข้อมูลรับรองที่เก็บใน vault ฉีดนอกโมเดล — เอเจนต์ไม่เคยเห็นคีย์ดิบ |
| **การควบคุมต้นทุน** | ติดตามด้วยมือ ไม่มีขีดจำกัดเข้มงวด | งบประมาณเครดิตรายเอเจนต์ที่เครดิตละ $0.001 พร้อมตัดอัตโนมัติ |
| **การจัดวง** | เขียน logic การ route เอง หรือใช้การ route ด้วย LLM | การประสานงานแบบเป้าหมายและงาน (เป้าหมาย → งาน → เอเจนต์) — ตรวจสอบได้ |
| **การสังเกตการณ์** | ผสาน LangSmith, Datadog หรือ logging แบบกำหนดเอง | แดชบอร์ดในตัวพร้อม streaming สด, กราฟต้นทุน, request trace |
| **การดีพลอยหลายช่องทาง** | สร้างการผสานรายช่องทาง | แชทบนเว็บทุกแพลน, Telegram และ webhook ตั้งแต่ Pro, Slack และอีเมลขาเข้าบน Team ขึ้นไป |
| **Browser automation** | ตั้งค่า Playwright/Puppeteer จัดการอินสแตนซ์ Chrome | ไม่มีให้ตอนเปิดตัว — เอเจนต์อ่านเว็บสดด้วยการค้นหาและดึงข้อมูลในตัวแทน |
| **ขยายเครื่องมือ** | สร้างการผสานแบบกำหนดเองหรือใช้เครื่องมือ LangChain | มีในตัว — ค้นหาและดึงข้อมูลเว็บ, ไฟล์, หน่วยความจำ, ตารางเวลา, การรันโค้ดในแซนด์บ็อกซ์, ผลงานที่แชร์ได้ |
| **หน่วยความจำเอเจนต์** | สร้าง RAG หรือการจัดการ state แบบกำหนดเอง | หน่วยความจำเวกเตอร์ถาวรรายเอเจนต์พร้อมการจัดการ context อัตโนมัติ |
| **Model failover** | logic retry แบบกำหนดเองรายผู้ให้บริการ | จัดการโดยแพลตฟอร์ม — เลือกพรีเซ็ตแล้วมัน route ให้คุณ |

สรุป: หากคุณกำลังประเมิน [AI agent framework](/learn/ai-agent-frameworks) และพบว่าตัวเองสร้างโครงสร้างพื้นฐานมากกว่า logic ของเอเจนต์ คุณกำลังแก้ปัญหาแพลตฟอร์มด้วยเครื่องมือ framework OpenLegion จัดการชั้นแพลตฟอร์มเพื่อให้คุณโฟกัสที่สิ่งที่เอเจนต์ของคุณทำจริง

## ขยายเครื่องมือในตัว

OpenLegion ส่งเครื่องมือมาพร้อมแพลตฟอร์มแทนที่จะให้คุณตั้งค่าเซิร์ฟเวอร์เอง เอเจนต์ทุกตัวมีการค้นหาและดึงข้อมูลเว็บ, การจัดการไฟล์, หน่วยความจำระยะยาว, ตารางเวลา, การรันโค้ดในแซนด์บ็อกซ์ และผลงานที่แชร์ได้ตั้งแต่วินาทีที่ถูกสร้าง ตัวเชื่อมตอนเปิดตัวคือ Google Calendar และไฟล์ใน Google Drive ที่คุณเลือก; Model Context Protocol (MCP) ยังไม่รองรับตอนเปิดตัว

เครื่องมือในตัวหมายความว่าเอเจนต์ใช้งานได้ทันทีที่คุณสร้างมัน โดยไม่มีอะไรต้องติดตั้งและไม่มีอะไรต้องตั้งค่า ทุกการเรียกเครื่องมือเป็นเจตนาที่ policy engine เดียวตรวจสอบก่อนเกิดขึ้น เอเจนต์จึงอยู่ในขอบเขตสิทธิ์และทุกการเรียกถูกบันทึกเป็นใบเสร็จ

## หน่วยความจำเอเจนต์ถาวร

เอเจนต์ใน OpenLegion รักษาหน่วยความจำข้ามเซสชันโดยใช้ vector search, ไฟล์ workspace และการเรียนรู้จากข้อผิดพลาด เมื่อเอเจนต์เจอปัญหาและแก้ไขได้ วิธีแก้จะถูกเก็บและเรียกคืนในเซสชันในอนาคต — ลดความล้มเหลวซ้ำซ้อนและปรับปรุงคุณภาพการเรียกใช้งานเมื่อเวลาผ่านไป

หน่วยความจำมีขอบเขตรายเอเจนต์และแยกจากเอเจนต์อื่นทุกตัวและทุก workspace การจัดการ context อัตโนมัติทำให้การใช้ token มีประสิทธิภาพโดยแสดงเฉพาะหน่วยความจำที่เกี่ยวข้องกับงานปัจจุบัน แทนการโหลดประวัติการสนทนาทั้งหมด

## สถาปัตยกรรม: Policy Engine เดียวหน้าทุกการกระทำ

OpenLegion แยกแต่ละ workspace เป็นขอบเขตความเชื่อมั่นสี่ชั้นบวก tier การตัดสินใจของเจ้าของ:

**Input ภายนอกที่ไม่เชื่อถือ** อะไรก็ตามที่มาจากผู้ใช้หรือบุคคลที่สาม: แชทบนเว็บ, Telegram, Slack, อีเมลขาเข้า และ webhook endpoint Input ทั้งหมดถูก validate และกรองผ่าน prompt-injection guard ก่อนถึง policy engine

**การรันของเอเจนต์ (ไม่เชื่อถือ)** แต่ละงานรันตามต้องการแล้วหยุด และโค้ดที่เอเจนต์เขียนรันในแซนด์บ็อกซ์ที่ไม่มีการเข้าถึงเครือข่ายเป็นค่าเริ่มต้น แม้แต่การรันที่ถูกบุกรุกเต็มที่ก็ไม่สามารถเข้าถึง API key ของคุณ ข้อมูลของเอเจนต์อื่น หรือ workspace อื่น

**Policy engine (เชื่อถือ)** ชั้นเดียวที่ตรวจสอบทุกการกระทำเป็นเจตนาก่อนเกิดขึ้นและบันทึกเป็นใบเสร็จที่เจ้าของอ่านได้: การเรียกเครื่องมือ, การมอบหมาย, การอนุมัติ, ต้นทุน มันถือบันทึกเป้าหมายและงานร่วมกัน, credential vault, เมทริกซ์สิทธิ์ และงบประมาณเครดิตของเอเจนต์แต่ละตัว นี่คือสมอง — และเป็นคอมโพเนนต์เดียวที่แตะ API key ของคุณ

**การตัดสินใจของเจ้าของหรือผู้ดูแลระบบ** งานจะหยุดรอการอนุมัติที่กำแพงสามจุดเท่านั้น: การติดต่อบุคคลที่สามแทนคุณ, การลบข้อมูล และการกระทำต่อเนื้อหาที่ไม่น่าเชื่อถือ การตัดสินใจเกิดขึ้นในแอปโดยเจ้าของหรือผู้ดูแลระบบ ไม่ใช่โดยเอเจนต์

**Control plane ภายในเท่านั้น** tier ที่จำกัดที่สุด: การดำเนินการด้านการดูแลระบบ เช่น การสร้างเอเจนต์ การให้สิทธิ์เครื่องมือ และการเปลี่ยนแพลน เข้าถึงผ่าน admin API เดียวที่มีขอบเขตอยู่ใน workspace เดียว

สถาปัตยกรรมนี้หมายความว่า[การจัดวง AI agent](/learn/ai-agent-orchestration)และความปลอดภัยไม่ใช่เรื่องแยกกัน — พวกเขาคือระบบเดียวกัน

## คำถามที่พบบ่อย

### AI agent platform คืออะไร

AI agent platform คือโครงสร้างพื้นฐานแบบจัดการให้ที่จัดการเรื่องเชิงปฏิบัติการของการรัน AI agent อัตโนมัติ: การแยกคอนเทนเนอร์, การจัดการข้อมูลรับรอง, การควบคุมต้นทุน, การจัดวง และการสังเกตการณ์ มันอยู่เหนือ framework อย่าง LangGraph หรือ CrewAI และให้ชั้นโปรดักชันที่ framework ทิ้งไว้ให้คุณ

### AI agent platform ที่ดีที่สุดสำหรับโปรดักชันคืออะไร

AI agent platform ที่ดีที่สุดสำหรับโปรดักชันขึ้นอยู่กับข้อกำหนดด้านความปลอดภัยและการดำเนินงานของคุณ หากคุณต้องการการแยกการรันในตัว, ข้อมูลรับรองที่เก็บใน vault และการควบคุมงบประมาณรายเอเจนต์โดยไม่ต้องสร้างโครงสร้างพื้นฐานแบบกำหนดเอง OpenLegion ให้สิ่งเหล่านี้ออกจากกล่อง สำหรับทีมที่ลงทุนลึกในระบบนิเวศ Microsoft Azure AI Agent Service ควรประเมิน สำหรับความยืดหยุ่นสูงสุดพร้อมความพยายาม DIY มากขึ้น การ self-host LangGraph กับ LangSmith ให้การสังเกตการณ์ที่แข็งแกร่ง

### Enterprise AI agent platform คืออะไร

Enterprise AI agent platform เพิ่มการกำกับดูแล, การปฏิบัติตาม และการควบคุมความปลอดภัยบนชั้นการจัดวงเอเจนต์พื้นฐาน ข้อกำหนดสำคัญรวมถึง: การแยกข้อมูลรับรอง (เอเจนต์ไม่ควรเห็น API key ดิบ), ความสามารถในการติดตามเวิร์กโฟลว์, การบังคับงบประมาณเพื่อป้องกันต้นทุนหลุดควบคุม, การควบคุมการเข้าถึงตาม role และตัวเลือกการดีพลอยที่รองรับข้อกำหนดด้านที่อยู่ของข้อมูล สถาปัตยกรรม OpenLegion ออกแบบมาสำหรับสภาพแวดล้อมที่ต้องการการควบคุมเหล่านี้

### ฉันโฮสต์ AI agent ด้วย API key ของตัวเองได้หรือไม่

ไม่ และคุณไม่จำเป็นต้องทำ การเข้าถึงโมเดลรวมอยู่แล้ว: เลือกพรีเซ็ต — Smartest, Smart หรือ Normal — ต่อเอเจนต์หรือต่อ workspace แล้ว OpenLegion จัดการผู้ให้บริการให้ งานถูกคิดเป็นเครดิต เครดิตละ $0.001 คุณจึงเห็นต้นทุนที่แน่นอนของทุกงาน แพลนฟรีคือ $0 พร้อม 1,000 เครดิตครั้งเดียวโดยไม่ต้องใช้บัตร

### AI agent แบบจัดการให้ vs self-host: ต่างกันอย่างไร

AI agent platform แบบจัดการให้จัดการการ provision คอนเทนเนอร์, การ vault ข้อมูลรับรอง, การควบคุมต้นทุน และการสังเกตการณ์ให้คุณ Self-host หมายถึงคุณดีพลอย framework (LangGraph, CrewAI, AutoGen) บนโครงสร้างพื้นฐานของคุณเองและสร้างชั้นเชิงปฏิบัติการเหล่านี้เอง แบบจัดการให้เร็วกว่าในการเข้าโปรดักชันและต้องการการลงทุน DevOps น้อยกว่า Self-host ให้การควบคุมโครงสร้างพื้นฐานสูงสุด OpenLegion เป็นแบบจัดการให้: คุณเข้าสู่ระบบด้วย Google แล้วเริ่มได้เลย และเอนจินที่อยู่ข้างใต้เผยแพร่แบบ source-availaม: โค้ดที่เปิดเผยซอร์สโค้ด (PolyForm Perimeter License 1.0.1) ที่คุณ self-host ได้พร้อมความสามารถของแพลตฟอร์มแบบจัดการให้ในตัว

### OpenLegion เทียบกับแพลตฟอร์ม AI agent อื่นอย่างไร

OpenLegion แตกต่างที่สถาปัตยกรรมที่เน้นความปลอดภัยเป็นอันดับแรก จากเอกสารสาธารณะในเวลาที่เขียน ไม่มี [AI agent framework](/learn/ai-agent-frameworks) หลักอื่นที่ให้ข้อมูลรับรองที่เก็บใน vault ในตัว, การรันในแซนด์บ็อกซ์สำหรับทุกงาน หรือการบังคับงบประมาณรายเอเจนต์เนทีฟ ดู[การเปรียบเทียบ framework](/learn/ai-agent-frameworks)สำหรับการแยกย่อยโดยละเอียดข้าม OpenClaw, LangGraph, CrewAI, AutoGen และ Semantic Kernel

### OpenLegion ใช้ใบอนุญาตอะไร

เอนจินของ OpenLegion เผยแพร่แบบ source-available ภายใต้ใบอนุญาต PolyForm Perimeter License 1.0.1 บน [GitHub](https://github.com/openlegion-ai/openlegion) แพลตฟอร์มที่โฮสต์ให้เป็นกรรมสิทธิ์ และเป็นที่ที่ทีมรันเอเจนต์โดยไม่ต้องดูแลโครงสร้างพื้นฐานใด ๆ เอง

### ฉันดีพลอยเอเจนต์แรกได้เร็วแค่ไหน

ไม่กี่นาที โดยไม่มีอะไรต้องติดตั้ง เข้าสู่ระบบด้วย Google บอกผู้ช่วยว่าคุณต้องการให้ทำอะไร แล้วมันจะสร้างเอเจนต์ที่ต้องการ แพลนฟรีคือ $0 พร้อม 1,000 เครดิตครั้งเดียวโดยไม่ต้องใช้บัตร จึงไม่มีอะไรขวางระหว่างการเข้าสู่ระบบกับงานแรกของคุณ
