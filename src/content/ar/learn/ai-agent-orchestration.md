# تنسيق وكلاء الذكاء الاصطناعي: تنسيق وحوكمة والتحكم في أساطيل الوكلاء

عندما يشغّل وكيل ذكاء اصطناعي واحد مهمة، يكون التنسيق بسيطاً — لا يوجد شيء للتنسيق. في اللحظة التي تنشر فيها وكيلين أو أكثر يحتاجون إلى مشاركة السياق، أو تسليم المهام، أو التصرّف على نفس البيانات، يصبح التنسيق المشكلة الهندسية المركزية. وليس فقط حول توجيه الرسائل.

**تنسيق وكلاء الذكاء الاصطناعي** هو النظام الذي يقرر أي وكيل يعمل، ومتى، وبأي بيانات، تحت أي قيود، وبأي تكلفة. يعامل OpenLegion التنسيق على أنه لا ينفصل عن الأمان: كل إجراء نيّة يفحصها محرّك سياسات واحد قبل وقوعها، ثم تُسجَّل كإيصال يمكن للمالك قراءته. وتُختار النماذج عبر إعدادات مسبقة — الأذكى أو ذكي أو عادي.

> **ما هو تنسيق وكلاء الذكاء الاصطناعي؟**
> تنسيق وكلاء الذكاء الاصطناعي هو طبقة التنسيق التي تدير تعيين المهام، وتدفق البيانات، والتسلسل، والحوكمة عبر وكلاء ذكاء اصطناعي مستقلين متعددين. يحدد أي وكيل يتعامل مع كل مهمة، ويفرض ضوابط الوصول، ويتتبع التكاليف، ويحافظ على الحالة المشتركة — محوّلاً الوكلاء المستقلين إلى أسطول مُحكم.

## الخلاصة

- **التنسيق = التنسيق + الحوكمة.** توجيه الوكلاء دون التحكم في بيانات الاعتماد والميزانيات والعزل ليس تنسيقاً — إنه مسؤولية.
- **تنسيق قائم على الأهداف والمهام** — يوجّه OpenLegion العمل على هيئة أهداف ← مهام ← وكلاء، مع مساعد يفوّض. لا "وكيل رئيس تنفيذي" من LLM يتخذ قرارات توجيه غامضة.
- **تنسيق مدفوع بالأهداف** — تنفيذ تسلسلي ومتوازٍ من سجل مشترك واحد للأهداف والمهام، مع إيقاظ بالأحداث. تفويض، وليس هرمية.
- **عزل بيانات الاعتماد اعتبار تنسيق** — عندما يسلّم الوكيل A إلى الوكيل B، لا ينبغي أن يرى أي منهما مفاتيح API للآخر أو أن يتمكّن من تصعيد الأذونات.
- **ضوابط تكلفة لكل وكيل** — يحمل كل وكيل في الفريق ميزانية أرصدة خاصة به مع قطع صارم. لا يستنزف وكيل جامح حسابك بأكمله.
- **حالة مشتركة عبر الأهداف والمهام** — تتواصل الوكلاء عبر سجل مشترك واحد للأهداف والمهام، تُوقظها الأحداث. لا توجد اتصالات مباشرة بين وكيل ووكيل.

## ما الذي يجعل تنسيق وكلاء الذكاء الاصطناعي مختلفاً عن أتمتة سير العمل

تنقل أتمتة سير العمل التقليدية (Zapier، n8n، Make) البيانات بين خطوات محددة مسبقاً. تقوم كل خطوة بشيء واحد بالضبط، في كل مرة. النظام حتمي بالتصميم.

يضيف تنسيق الذكاء الاصطناعي الوكيلي طبقة استقلالية. يمكن لكل وكيل في سير العمل اتخاذ قرارات، واستدعاء أدوات، وتوليد محتوى، واتخاذ إجراءات لم تُبرمَج صراحةً. هذه الاستقلالية هي الهدف بأكمله — وهي أيضاً ما يجعل التنسيق خطيراً دون ضوابط مناسبة.

عندما يستطيع وكيل أن يقرر استدعاء API خارجية، أو الكتابة إلى قاعدة بيانات، أو تصفّح الويب، تحتاج طبقة التنسيق إلى الإجابة على أسئلة لم تواجهها أدوات سير العمل التقليدية أبداً:

- هل لدى هذا الوكيل إذن باستخدام هذه الأداة؟
- هل يجب أن يرى هذا الوكيل بيانات اعتماد تلك الـ API؟
- كم أنفق هذا الوكيل اليوم، وهل يجب أن يستمر؟
- إذا اختُرق هذا الوكيل عبر حقن موجّه، ما نطاق التأثير؟

لهذا السبب يعامل OpenLegion [أمان وكلاء الذكاء الاصطناعي](/learn/ai-agent-security) والتنسيق على أنهما نفس النظام، وليس وحدتين منفصلتين مُركَّبتين بعد وقوع الفعل.

## أنماط تنسيق وكلاء الذكاء الاصطناعي

### التنسيق التسلسلي

تنفّذ الوكلاء واحداً بعد الآخر بترتيب محدد. مخرجات كل وكيل تصبح مدخلات الوكيل التالي. الأفضل لخطوط الأنابيب ذات نقاط التسليم الواضحة.

**مثال: خط أنابيب إنتاج محتوى.**
وكيل الباحث ← وكيل الكاتب ← وكيل المحرر. يجمع الباحث المصادر وينتج موجزاً. يُنتج الكاتب مسودة من الموجز. يراجع المحرر ويخرج نسخة نهائية. تعمل كل مهمة عند الطلب في تشغيل خاص بها داخل صندوق رمل، ترى فقط بيانات اعتمادها الخاصة، ولها ميزانية أرصدة خاصة بها.

### التنسيق المتوازي

تعمل وكلاء متعددة في وقت واحد على مهام فرعية مستقلة. تندمج النتائج عند نقطة تزامن. الأفضل للمهام التي تتحلل إلى تدفقات عمل مستقلة.

**مثال: تحليل تنافسي.**
ثلاثة وكلاء بحث يعملون بالتوازي — واحد لكل منافس — كل منهم يكشط الوثائق العامة، ومستودعات GitHub، وصفحات التسعير. ينتظر وكيل التركيب اكتمال الثلاثة، ثم ينتج مقارنة موحَّدة. يعمل كل وكيل متوازٍ عبر تشغيل مهمة خاص به في صندوق رمل بسقف ميزانية خاص به.

### التنسيق القائم على الأهداف والمهام ورسائل الأحداث

ينظّم OpenLegion العمل على هيئة أهداف ← مهام ← وكلاء، لا كهرمية. تتواصل جميع الوكلاء عبر سجل مشترك واحد للأهداف والمهام، وكل مهمة إيقاظ بحدث يفحصه محرّك السياسات قبل تشغيلها. لا يوجد "وكيل رئيس تنفيذي" أو وكيل مشرف يتخذ قرارات التوجيه — ينشئ مساعد الزملاء الذين يحتاجهم ويفوّض إليهم، ويوفّر السجل المشترك السياق الذي تقرأ منه الوكلاء وتكتب إليه أثناء التنفيذ. يبقي هذا التنسيق قابلاً للتدقيق.

## لماذا العزل والخزنة وضوابط الميزانية هي اعتبارات تنسيق

تعامل معظم [أطر وكلاء الذكاء الاصطناعي](/learn/ai-agent-frameworks) الأمان كشيء تضيفه بعد أن يعمل التنسيق. توجيه الوكلاء وحدة. إدارة بيانات الاعتماد اهتمام منفصل. تتبع التكلفة إضافة للرصد.

هذا الفصل خاطئ معمارياً. إليك السبب:

### عزل بيانات الاعتماد أثناء التسليم

عندما يكمل الوكيل A مهمة ويسلّم إلى الوكيل B، تدير طبقة التنسيق الانتقال. إذا تشارك كلا الوكيلين نفس مساحة العملية (كما في CrewAI crews أو LangGraph graphs العاملة في عملية Python واحدة)، فلا توجد آلية لمنع الوكيل B من الوصول إلى بيانات اعتماد الوكيل A عبر الذاكرة المشتركة.

يفرض OpenLegion عزل بيانات الاعتماد على مستوى التنسيق. تعمل كل مهمة في تشغيل خاص بها داخل صندوق رمل. وتحقن الخزنة بيانات الاعتماد لكل وكيل، خارج النموذج — مفاتيح API للوكيل A ليست موجودة أبداً في تشغيل الوكيل B. وتوجّه طبقة التنسيق التسليم عبر محرّك السياسات، وليس عبر اتصال مباشر بين وكيل ووكيل.

### فرض الميزانية كمنطق تنسيق

في سير عمل متعدد الوكلاء، تتوزع تكاليف الرموز بشكل غير متساوٍ. قد يستهلك وكيل البحث 10 أضعاف رموز وكيل التنسيق. بدون ميزانيات لكل وكيل، يمكنك فقط ضبط حد عالمي — مما يعني أن وكيلاً ثرثاراً يمكن أن يجوّع الآخرين.

يتتبع OpenLegion الإنفاق لكل وكيل في الوقت الفعلي، مقيساً بأرصدة بقيمة $0.001 للرصيد. عندما يستنفد وكيل ميزانيته، توقف المنصة ذلك الوكيل المحدد وتعيد توجيه أو توقف سير العمل مؤقتاً — دون قتل خط الأنابيب بأكمله. هذا منطق تنسيق، وليس مجرد رصد.

### فرض الأذونات عبر الأسطول

في التنسيق القائم على الأهداف والمهام (أهداف ← مهام ← وكلاء)، لكل وكيل مجموعة أذونات محددة. تحدد الأذونات لكل وكيل أي أدوات يمكنه استدعاؤها، وأي ملفات يمكنه الوصول إليها، وأي إجراءات مسموح له بأدائها. ويفرض محرّك سياسات واحد هذه القيود أمام كل إجراء.

يعني هذا أنه يمكنك تدقيق سير العمل بأكمله بشكل ثابت — قبل أن يعمل أي وكيل — والتحقق من أنه لا يملك أي وكيل أذونات لا ينبغي أن تكون له.

## سير عمل متعدد الوكلاء ملموس: فريق تطوير

إليك كيف يبدو سير عمل فريق التطوير في OpenLegion، من إنشاء المشروع إلى النشر:

**الخطوة 1: حدّد الفريق في التطبيق.**
ثلاثة وكلاء: PM (مدير المشروع)، مهندس، مراجع. يحلل PM المهام. يكتب المهندس الشيفرة. يدقق المراجع المخرجات.

**الخطوة 2: حدّد الأذونات لكل وكيل.**
يمكن لـ PM قراءة ملفات المشروع وإنشاء المهام. يمكن للمهندس تنفيذ الشيفرة في صندوق رمل وكتابة الملفات. يمكن للمراجع قراءة جميع المخرجات لكن لا يمكنه تنفيذ شيفرة أو إجراء استدعاءات API خارجية.

**الخطوة 3: حدّد الميزانيات لكل وكيل.**
PM: ميزانية أرصدة صغيرة (تخطيط في الغالب، استخدام رموز منخفض). المهندس: ميزانية كبيرة (توليد شيفرة كثيف). المراجع: ميزانية متوسطة (تحليل وتعليقات). ويمنع رصيد مساحة العمل التجاوزات التراكمية.

**الخطوة 4: ابدأ الفريق.**
إنشاء الوكلاء الثلاثة فوري — فهم سجلات دائمة لا خوادم — وتحقن الخزنة بيانات الاعتماد المناسبة في كل تشغيل، خارج النموذج. تعرض لوحة التحكم استخدام الرموز في الوقت الفعلي، وتتبع التكلفة، والمخرجات المتدفقة لكل وكيل.

**الخطوة 5: المراقبة والتدقيق.**
يعني التنسيق القابل للتدقيق القائم على الأهداف والمهام أن كل خطوة من سير العمل صريحة وقابلة للتتبع. ويُسجَّل كل استدعاء أداة وتفويض وموافقة كإيصال مع هوية الوكيل وطابع زمني والتكلفة الدقيقة — دون تحليل سجلات قرار LLM الغامضة.

| **إدارة بيانات الاعتماد** | خزنة بيانات اعتماد — حقن أعمى | متغيرات بيئة | متغيرات بيئة | متغيرات بيئة |

| **متعدد القنوات** | دردشة الويب، Telegram، ويب هوك، Slack، البريد الوارد | يتطلب تكاملاً مخصّصاً | يتطلب تكاملاً مخصّصاً | يتطلب تكاملاً مخصّصاً |

للفرق التي تقيّم أطر تنسيق الذكاء الاصطناعي الوكيلي، العامل المميّز الرئيسي هو ما إذا كانت طبقة التنسيق تحكم الوكلاء أم تقوم فقط بتوجيه الرسائل بينهم. يوفّر LangGraph أكثر تحكم برمجي مرونة. يقدّم CrewAI أكثر تصميم بديهي قائم على الأدوار. يعطي AutoGen أنماط محادثة. يضيف OpenLegion الحوكمة — العزل، وبيانات الاعتماد، والتكلفة — كبدائيات تنسيق أصلية.

## الأسئلة المتكررة

### ما هو تنسيق وكلاء الذكاء الاصطناعي؟

تنسيق وكلاء الذكاء الاصطناعي هو طبقة التنسيق التي تدير كيفية عمل وكلاء ذكاء اصطناعي مستقلين متعددين معاً. تتعامل مع تعيين المهام، والتسلسل، وتدفق البيانات بين الوكلاء، والتحكم في الوصول، وتتبع التكلفة، وإدارة الحالة المشتركة. بدون التنسيق، الأنظمة متعددة الوكلاء هي فقط وكلاء معزولون يعملون بشكل مستقل.

### ما هو تنسيق الذكاء الاصطناعي الوكيلي؟

يشير تنسيق الذكاء الاصطناعي الوكيلي تحديداً إلى تنسيق وكلاء ذكاء اصطناعي يتمتعون بالاستقلالية — وكلاء يمكنهم اتخاذ قرارات، واستدعاء أدوات، واتخاذ إجراءات تتجاوز الخطوات المحددة مسبقاً. على عكس أتمتة سير العمل التقليدية، يجب أن يأخذ التنسيق الوكيلي في الاعتبار سلوك الوكيل غير المتوقع، مما يتطلب عزل بيانات الاعتماد، وفرض الأذونات، وضوابط الميزانية على طبقة التنسيق.

### ما هي منصة تنسيق وكلاء الذكاء الاصطناعي؟

منصة تنسيق وكلاء الذكاء الاصطناعي توفّر بنية تحتية مُدارة لتنسيق سير عمل متعدد الوكلاء. بخلاف التوجيه الأساسي، تتعامل المنصة مع توفير الحاويات، وتخزين بيانات الاعتماد، وتتبع التكلفة، والرصد. OpenLegion هو [منصة وكلاء ذكاء اصطناعي](/learn/ai-agent-platform) تعامل التنسيق والحوكمة كنفس النظام — تمر كل قرارات التوجيه عبر العزل وضوابط التكلفة.

### كيف تنسّق وكلاء ذكاء اصطناعي متعددين في الإنتاج؟

في الإنتاج، يتطلب تنسيق تعدد الوكلاء أربعة أشياء بخلاف نموذج أولي يعمل: عزل وقت التشغيل (كل وكيل في حاويته الخاصة)، فصل بيانات الاعتماد (لا مفاتيح API مشتركة بين الوكلاء)، فرض الميزانية (حدود تكلفة لكل وكيل مع قطع صارم)، وتوجيه مهام قابل للتدقيق. يتعامل OpenLegion مع الأربعة عبر التنسيق القائم على الأهداف والمهام (أهداف ← مهام ← وكلاء)، وتشغيل في صندوق رمل لكل مهمة، وخزنة بيانات اعتماد تحقن خارج النموذج.

### كيف تعمل ضوابط التكلفة في تنسيق وكلاء الذكاء الاصطناعي؟

يفرض OpenLegion ميزانية أرصدة لكل وكيل مع قطع تلقائي صارم. عندما يصل وكيل إلى حده، توقف المنصة ذلك الوكيل المحدد دون قتل بقية خط الأنابيب. يمنع هذا وكيلاً ثرثاراً واحداً من استهلاك ميزانية المشروع بأكملها. تُتتبع التكاليف في الوقت الفعلي والتكلفة الدقيقة لكل مهمة ظاهرة.

### ما الفرق بين التنسيق القائم على LLM والتنسيق القائم على الأهداف والمهام (أهداف ← مهام ← وكلاء)؟

يستخدم التنسيق القائم على LLM نموذج ذكاء اصطناعي ("وكيل رئيس تنفيذي") لتقرير أي وكيل يتعامل مع كل مهمة في وقت التشغيل. هذا مرن لكنه غامض — لا يمكنك التنبؤ بقرارات التوجيه أو تدقيقها مسبقاً. يستخدم التنسيق القابل للتدقيق القائم على الأهداف والمهام قواعد محددة مسبقاً (أهداف ← مهام ← وكلاء في حالة OpenLegion) قابلة للتدقيق قبل أن يعمل أي وكيل. تعرف بالضبط أي وكيل يتعامل مع ماذا، تحت أي شروط، بأي أذونات.

### هل يمكنني استخدام OpenLegion لتنسيق متعدد الوكلاء مع أي LLM؟

لا تختار مزوّداً — تُختار النماذج عبر إعدادات مسبقة، الأذكى أو ذكي أو عادي، لكل وكيل أو لكل مساحة عمل. يمكنك تعيين إعدادات مسبقة مختلفة لوكلاء مختلفين في نفس سير العمل — على سبيل المثال، "الأذكى" لمهام الاستدلال المعقّدة و"عادي" لتصنيف عالي الحجم. لا توجد مفاتيح API تحضرها أو تديرها، وكل مهمة تعرض تكلفتها الدقيقة.

### كيف يقارَن تنسيق OpenLegion بـ LangGraph؟

يستخدم LangGraph StateGraph برمجياً حيث العقد هي دوال Python والحواف تحدد الانتقالات. يقدّم تحكماً قوياً في الحالة والتدفق لكنه لا يوفّر عزلاً مدمجاً، أو إدارة بيانات اعتماد، أو ضوابط تكلفة. يستخدم OpenLegion التنسيق القائم على الأهداف والمهام — أهداف ← مهام ← وكلاء — مع تشغيل في صندوق رمل لكل مهمة، وبيانات اعتماد من خزنة تُحقن خارج النموذج، وميزانيات لكل وكيل كميزات تنسيق أصلية. يمنح LangGraph مرونة برمجية أكثر؛ يضيف OpenLegion الحوكمة كاعتبار تنسيق من الدرجة الأولى.
