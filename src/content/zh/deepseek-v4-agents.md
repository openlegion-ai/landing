# 在 OpenLegion 上安全运行基于 DeepSeek 的智能体

**基于 DeepSeek 的智能体**将 DeepSeek 的模型与自主工具使用相结合——OpenLegion 是为它们提供安全保障的 AI 智能体框架。密钥库托管的凭证、每个任务一次沙箱化运行和单智能体预算控制默认开启。模型通过预设选择——最智能、智能或普通——工作按积分计量，每积分 $0.001。

<!-- SCHEMA: DefinitionBlock -->

> **什么是基于 DeepSeek 的智能体？**
> 基于 DeepSeek 的智能体是由 DeepSeek 模型（例如 `deepseek-chat` 或 `deepseek-coder`）驱动的自主 AI 智能体。当通过 OpenLegion 这样的 AI 智能体框架部署时，它们能执行多步任务、调用 API、生成代码和处理输入——并在平台层面强制执行每个任务一次沙箱化运行和凭证密钥库托管。

## 摘要

- **按预设路由模型。** OpenLegion 让每个智能体运行在一档模型预设上——最智能、智能或普通——可按智能体或按工作区选择，无需接线任何提供商账号或端点。
- **密钥库托管的凭证。** 凭证永远不会进入模型的上下文。它保存在密钥库中，并在模型之外注入，模型自始至终只持有一个句柄。
- **沙箱化运行。** 每个任务按需运行然后停止，智能体编写的任何代码都默认运行在无网络访问的沙箱中。
- **单智能体预算控制。** 每个智能体都有自己的积分预算，带自动硬性截止——对于迭代次数不可预测的智能体工作负载至关重要。
- **与具体模型无关的安全。** 无论预设背后是哪个模型，OpenLegion 都提供相同的 [AI 智能体安全](/learn/ai-agent-security) 保障：密钥库托管的凭证、沙箱化运行，以及为每个动作留下的回执。
- **模型无关。** 相同智能体、相同工具、相同安全——在应用中把智能体在各档预设之间移动即可。对于成本敏感的智能体团队，更便宜的模型往往是正确选择。

## 为什么基于 DeepSeek 的智能体需要安全框架

### 能力强、影响面广

具备工具访问能力的 DeepSeek 驱动智能体可以：
- 读写其工作区中的文件
- 生成并执行代码
- 访问 API、数据库和外部服务（受其权限约束）
- 在大上下文上推理

如果没有合适的 [AI 智能体运行时](/learn/ai-agent-platform)，自主智能体还可能：
- 尝试访问你的 API 密钥和凭证
- 在计量端点上累积无界的 API 成本
- 在运行时缺乏隔离的情况下影响其他智能体或主机
- 执行未经审计的工作流路径
- 在用户提供的上下文中遭遇提示注入

OpenLegion——一个托管的 AI 智能体平台——通过三层架构保障来应对：

**密钥库托管的凭证。** 你的凭证永远不会进入模型的上下文。它们保存在密钥库中，并在模型之外注入，模型自始至终只持有一个句柄。即使模型被诱导去寻找凭证，这次运行里也无任何可找之物。

**沙箱化的任务运行。** 每个任务按需运行然后停止，智能体编写的任何代码都默认运行在无网络访问的沙箱中。被攻陷的智能体无法影响其他智能体、平台或你的凭证密钥库。

**单智能体预算执行。** 每个智能体都有自己的积分预算，并自动硬性截止。没有任何智能体能在一夜之间烧穿你的积分。

## DeepSeek 模型配置说明

DeepSeek 发布了诸如 `deepseek-chat` 和 `deepseek-coder` 之类的模型，并定期发布以推理为重点的版本。具体的模型阵容和定价会随时间变化；请参阅 [DeepSeek 文档](https://api-docs.deepseek.com/) 获取最新列表。智能体工作负载的关键实用考虑：

- **路由。** OpenLegion 按预设路由。你为智能体挑选最智能、智能或普通，平台就运行其背后的模型；没有模型 ID 或聚合器账号需要管理。
- **上下文窗口和定价** 因模型而异。请查阅 DeepSeek 文档获取当前每 token 成本；无论使用哪个模型，OpenLegion 的单智能体预算都是安全网。
- **开放权重。** 某些 DeepSeek 模型系列已发布开放权重，团队可以用 Ollama 或 vLLM 在自有 GPU 上运行它们。OpenLegion 是托管的，运行你所选预设背后的模型——无论哪种方式，它的安全保障对每个任务都同样适用。

## 如何在 OpenLegion 上运行基于 DeepSeek 的智能体

在托管应用中配置智能体大约只需 30 秒——无需配置文件，无需编辑 YAML，也没有任何东西需要安装。用 Google 登录，第一个智能体就绪。

### 第 1 步：选择你的 LLM 提供商

其实没有提供商可选：OpenLegion 替你运行模型。你改为挑选一档预设——最智能、智能或普通——可按智能体或按工作区设置。这与驱动 OpenLegion 上所有 [智能体协调](/learn/ai-agent-orchestration) 的模型系统相同。

### 第 2 步：提供你的 API 密钥

没有模型 API 密钥要粘贴，开始使用也无需绑卡。你确实要添加的那些凭证——供智能体使用的工具凭证——保存在密钥库中并在模型之外注入，因此智能体自始至终只持有一个句柄，永远看不到原始密钥。

### 第 3 步：选择模型

为该智能体或整个工作区挑选你想要的预设——最智能、智能或普通。完成。你的智能体现在以密钥库托管的凭证、每个任务一次沙箱化运行和预算执行在跑——这是适用于 OpenLegion 所运行每个模型的同一套安全栈。

就是这样。应用负责模型，密钥库保管你的凭证，平台负责沙箱化和预算。

### 用开放权重在本地运行 DeepSeek

团队可以通过 Ollama、vLLM 或其他推理服务器在自有 GPU 上运行 DeepSeek 开放权重，把推理留在本地。OpenLegion 本身是托管的：没有自托管选项，也没有本地端点可以指向，每档预设背后的模型都在平台上运行。OpenLegion 贡献的是模型之外的一切——沙箱化运行、工具访问控制、委派，以及为每个动作留下的回执。

### 切换模型——把 DeepSeek 作为 Claude 或 GPT 的替代

想在同一任务上用更便宜的模型对比前沿模型？在应用中更改该智能体的预设即可。相同的智能体、相同的工具、相同的安全——模型不同。请参见我们的 [AI 智能体框架对比](/learn/ai-agent-frameworks) 了解各提供商的分析。

## 基于 DeepSeek 的智能体工作流

### 长上下文支持仓库级智能体

现代 DeepSeek 系列模型支持大上下文窗口，可启用以下智能体工作流：

- **整仓代码审查** 单次完成（当上下文窗口允许时）
- **跨文件重构** 具备更广的依赖感知
- **文档生成** 基于更大的项目上下文
- **跨代码库安全审计**

OpenLegion 把这些长上下文操作限制在边界内：每个任务按需运行然后停止，每次唤醒都由策略引擎检查并计量——同时单智能体预算可防止单条超大提示词消耗整个月度额度。

### 通过硬性截止实现成本可预测

DeepSeek 模型历来定价低于西方前沿替代方案，这使它们对高迭代智能体工作负载具有吸引力。但当智能体自由迭代时，"单次更便宜"仍可能变成"总体很贵"。OpenLegion 的单智能体积分预算和硬性截止可防止成本峰值在团队中级联扩散。

## 基于 DeepSeek 的智能体的安全考虑

### 开放权重既是特性也是风险面

DeepSeek 的开放权重发布对自托管部署和生态透明度是巨大优势。但它们也意味着：

- **微调变体会激增。** 并非所有变体都经过对齐或安全测试。无论预设背后是哪个模型，OpenLegion 的沙箱化运行和工具限制都会生效。
- **针对开放权重的对抗性研究更容易。** 运行开放权重模型的智能体受益于[纵深防御](/learn/ai-agent-security)：沙箱化运行、有界执行、显式工具授权——而不仅是模型级别的对齐。
- **供应链卫生。** 从 Hugging Face 或其他来源下载开放权重需要校验和与来源验证。请记录你运行的具体模型二进制。

### 长上下文扩大了提示注入面

大上下文窗口意味着大的潜在提示注入面。处理整个代码库的智能体会处理每条注释、每个字符串字面量、每份 README——其中任何一处都可能包含对抗指令。

OpenLegion 的防御：守在每个动作之前的统一策略引擎、单智能体工具权限、让注入无法窃取密钥的密钥库托管凭证，以及智能体在对不可信内容采取行动前的审批墙。即使注入成功，这些机制也限制了损害范围。

### 地缘政治考量

对于受出口管制、数据主权要求或供应链合规约束的组织，部署模式很重要：

- **API 模式：** 数据经过 DeepSeek 的托管基础设施。
- **自托管模式（开放权重）：** 数据留在你的基础设施。完全消除了 API 依赖。
- **聚合器/推理提供商模式：** 数据经过该提供商的基础设施（因提供商而异）。

OpenLegion 是托管的，推理在平台上运行，所有套餐都享有相同的 [AI 智能体安全](/learn/ai-agent-security) 保障。

## 常见问题

### 什么是基于 DeepSeek 的智能体？

基于 DeepSeek 的智能体是由 DeepSeek 模型（如 `deepseek-chat` 或 `deepseek-coder`）驱动的自主 AI 智能体，运行在提供隔离、凭证、工具、预算和协调的智能体框架之下。OpenLegion 就是这样的一个框架——它为你选择的任何模型预设添加每个任务一次沙箱化运行、密钥库托管的凭证和单智能体积分预算。

### OpenLegion 支持 DeepSeek 吗？

OpenLegion 替你运行模型，所以你从不需要选择提供商。你改为挑选一档预设——最智能、智能或普通——可按智能体或按工作区设置，平台会运行其背后的模型。没有 API 密钥要粘贴，没有聚合器账号要配置，也不需要自己搭推理服务器；工作按积分计量，每积分 $0.001，每个任务的确切成本都可见。

### 如何安全地运行基于 DeepSeek 的智能体？

OpenLegion 为每个智能体提供三层安全：密钥库托管的凭证（凭证永远不会进入模型的上下文——它留在密钥库中，并在模型之外注入）、沙箱化的任务运行（每个任务按需运行然后停止，智能体编写的代码默认无网络访问），以及单智能体预算执行（各自的积分预算，带自动硬性截止）。创建智能体、挑选预设，安全栈自动生效。

### 在智能体任务上，DeepSeek 比 Claude 或 GPT 更好吗？

取决于任务。DeepSeek 系列模型通常定价低于 Claude 和 GPT，在许多基准上具有竞争力，但具体能力因模型而异。对于智能体工作负载，选择取决于任务要求、成本约束和数据驻留需求。OpenLegion 对它运行的每个模型都应用一致的安全保障——你可以在相同工作流上并排评估各档预设。

### 我能在 OpenLegion 上自托管 DeepSeek 吗？

发布时还不行。OpenLegion 是一个托管 Web 应用：没有自托管选项，也没有本地端点可以指向。必须把推理留在自有 GPU 基础设施上的团队，可以在那里用 Ollama 或 vLLM 单独运行开放权重，与 OpenLegion 无关。在平台上你挑选一档预设，沙箱化运行、工具访问控制、委派和单智能体预算全部生效。

### 对于智能体工作负载，DeepSeek 的定价如何？

DeepSeek 在单 token 维度上通常定价低于西方前沿模型。对于涉及大量迭代 API 调用的智能体工作负载，成本差异会被放大。OpenLegion 的单智能体预算控制——每个智能体一份带硬性截止的积分预算——可防止智能体自由迭代时"单次更便宜"变成"总体很贵"。

### DeepSeek 是 AI 智能体的 Claude 替代方案吗？

对于成本敏感的智能体工作负载，DeepSeek 可以是一个有竞争力的替代方案。OpenLegion 对它运行的每个模型都应用相同的安全保障，因此你可以在相同工作流上并排评估各档预设，并在应用中切换，无需更改智能体或任何基础设施。

### 在中国 AI 模型上运行智能体安全吗？

安全性问题取决于你的部署模式。自托管的开放权重 DeepSeek 智能体意味着数据不离开你的基础设施。API 模式则将数据经过 DeepSeek 的托管服务器路由。OpenLegion 是托管的，运行你所选预设背后的模型，所有套餐都享有相同的安全保障。对于有数据主权要求的组织，使用开放权重的自托管部署可将推理保留在你的基础设施中。

### DeepSeek 的长上下文窗口对智能体有何用处？

大上下文窗口允许智能体工作流在一次处理整个代码库、完整文档集或长对话历史——无需切块或检索增强。OpenLegion 的有界执行和单智能体预算可防止昂贵的长上下文提示超出限额，无论使用的是哪个模型。
